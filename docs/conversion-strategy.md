# Conversion Strategy

Wie der öffentliche Auftritt Interesse in qualifizierte Leads verwandelt.

## Primäre Conversion

**Demo/Kontakt-Anfrage** (`/demo`) — Demo-first passt zur Zielgruppe.
Sekundär: **Early Access / Pilot** (dasselbe Formular, Auswahl „Early Access“).

## CTA-Strecken

| Einstieg | Weg | Ziel |
| --- | --- | --- |
| Home Hero | „Demo anfragen“ / „So funktioniert es“ | `/demo` bzw. `/product` |
| Produkt/Für-Garagen | `FinalCta` | `/demo` + `/pricing` |
| Pricing-Karten | stufengerechte CTAs | `/demo` |
| Header (dauerhaft) | „Demo anfragen“ | `/demo` |
| Footer | „Early Access“, „Zur App“ | `/demo`, `/dashboard` |

Jede Seite endet mit einer klaren Handlungsaufforderung; nie eine Sackgasse.

## Formular-Flow (Block 5: Placeholder)

`/demo` enthält ein Kontakt-/Early-Access-Formular. In Block 5 ist es ein
**sauberer Placeholder-Flow**: clientseitige Validierung + Bestätigungszustand,
**kein** Backend-Versand. Anbindung an Postfach/CRM/Resend ist eine
Provider-Entscheidung: <span>TODO PROVIDER DECISION</span> (Block 6).

Erfassungsfelder: Name*, Betrieb, E-Mail*, Telefon, Interesse
(Demo/Early-Access/Pricing/Partner), Nachricht.

## Vertrauen als Conversion-Hebel

- Ehrliche Trust-Elemente: Produktlogik, Sicherheit/Datenschutz, „für
  unabhängige Garagen“, Pilot-Transparenz.
- **Keine** erfundenen Testimonials/Logos/Zertifikate. Platzhalter-Struktur für
  spätere echte Fallbeispiele.
- Preistransparenz (Draft klar markiert) reduziert Reibung.

## Messung (später)

Ziele: Anfragen/Woche, Demo→Pilot-Rate, Pilot→zahlend-Rate. Analytics erst mit
Cookie-/Tracking-Konzept (siehe Datenschutz-Entwurf) — im Pilot bewusst schlank.

## Optimierungsideen (Backlog)

- Kurzes Demo-Video / interaktiver Kundenseiten-Vorschau-Block.
- FAQ nah an Pricing platzieren (Einwände am Entscheidungspunkt).
- Case-Study-Sektion, sobald echte Pilotdaten vorliegen.
